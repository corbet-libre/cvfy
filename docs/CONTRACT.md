# cvfy contract

`NativeVerifier::verify` accepts an ordered slice of canonical big-endian BN254 public field elements and proof bytes. `verify_batch_before` accepts at most 65 such pairs under one absolute `Instant` deadline. The smaller caller deadline and configured timeout covers validation, encoding, worker startup, all native verification, pipe completion and verdict validation. Success observed at or after expiry is refused. The caller independently enforces wall-clock policy and proof expiry.

The host authenticates circuit/key/setup provenance and supplies immutable RAM snapshots in `NativeVerifierConfig`. The constructor additionally verifies the key SHA-256 against its scope, and validates resource limits. `NativeCapacity` shares anonymous admission across clones and independently scoped verifiers; a whole batch retains its permit through cleanup. No durable replay, identity, budget or database state belongs here.

Each batch is limited to 4 MiB of proof bytes, 32,768 public fields and a fixed 26 MiB encoded envelope, with smaller per-proof bounds from the host. The fixed slice serializer cannot grow its allocation. The worker caps reads before parsing. Empty, oversized or noncanonical fields and unaligned proof bytes are rejected before native crypto. Proof chunks themselves are opaque upstream uint256 values, not locally reinterpreted as scalar fields.

The owned `czkp-bb-worker` uses maintained `barretenberg-rs` with the matching authenticated upstream static library. It initializes exactly one RAM CRS factory through `SrsInitSrs` and calls the official `CircuitVerify` for each proof using the existing `noir-recursive` Poseidon2/ZK settings. There is no partial success. It has no artifact paths, download/cache mechanism, database or member-controlled executable configuration. All owned Rust forbids unsafe; upstream FFI and C++ implement the existing cryptographic system.

The parent clears the worker environment and provides only explicit thread and address-space limits. The worker applies finite address-space and disabled core-dump limits before reading input. Stderr is discarded. Stdout is bounded to 4096 bytes and must contain the exact configured scope and successful verdict. Timeout or process error kills and reaps before joining pipe threads. The trusted executable must not spawn descendants that retain pipe handles. The executable must carry its required runtime library search paths; ambient dynamic-loader variables are not inherited.

The explicit `instrumented-worker` feature additionally forwards the host's `LLVM_PROFILE_FILE` for CI instrumentation only. It is not a production requirement. `test-worker` builds compiled refusing fixtures, never a substitute cryptographic verifier. Genuine proof acceptance is tested with retained upstream-generated account proofs; cblc also checks extension proofs and its independent domain-to-field mapping. Fixtures or mock verdicts never establish proof soundness.

The scope and executable are trust configuration: a fabricated `verified: true` from a substituted executable is not evidence. The library neither owns accounting policy nor claims a complete private-account relation. Domain validation and selective downstream projection belong to cblc.
